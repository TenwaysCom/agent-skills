# 发布简单项目改动

每轮交付使用一个 PR。部署后的补丁仍关联原 Issue，通过新一轮 PR 交付。按当前请求区分仅准备、仅合并、部署、检查和回退，不将调用 skill 当作全部操作的授权。

## 准备可审阅的发布结果

1. 读取项目交付规则、最新 Issue、本地待同步的需求和证据及实际 CI/CD 配置。以最后已确认的需求为准，冲突列为待澄清。核对仓库、PR、默认分支、候选完整 SHA、目标环境和发布入口。确认合并是否自动触发部署。需要 UAT PR 再到 main PR 或发布批次时，整理交接资料并转项目专用流程，不执行通用发布。
2. 核对当前候选的测试、review 和已有验收证据。必需检查、必需人工确认或阻塞发现未满足时，保持待处理。仅需部署后才能验证的 AC 可保留，但需明确部署后的检查及回退条件。
3. 读取项目已有部署和回退方式，列出发布版本、配置或数据变更、验证动作、失败处理及上一可用版本。不猜测远端命令。不可逆数据变更或无法执行的回退必须单独列为决策项，不能承诺代码回退能恢复数据。
4. 发布前补齐实际使用方法，并准备 Issue 的更新文本。用户只要求方案或准备时，到此交付准备结果，不执行合并或部署。

需要创建或更新 PR 时，先核对当前授权。将本轮改动集中到一个 PR，引用 `Refs #编号`，关联候选、验证与风险。同一轮复用尚未合并的 PR，不另建发布 PR。原 PR 已合并且仍有修复需要交付时，从当前目标分支建立补丁 PR，继续关联原 Issue，记录新的候选与验证；不能复用旧 PR 的最终 SHA 代表修复。只检查原次发布状态、没有新改动时，复用已合并记录，不新建 PR。默认不使用会提前关闭 Issue 的关键词。

缺少操作授权时，先完成以上准备，再只请求具体动作的授权。已有明确授权继续有效，不重复询问。合并会自动部署时，合并前确认当前授权涵盖该部署。外部写入使用现有连接器或已认证 CLI，正文通过结构化参数或文件传递。

## 同步候选交付

发布准备和局部修复先累计到本轮本地待同步记录。沿用项目约定的记录位置，没有约定时可使用 `.local/dev-records/issue-<编号>.md`，交付时提供路径。正式交付候选供 review 或验收时，核对已授权的 commit、push 已完成且远端 SHA 可读回，确认现有证据覆盖该候选，再集中同步需求变化、实现摘要、各阶段结论、剩余事项和 PR。普通 push 不单独触发同步。推送失败时保留未同步状态，不宣称候选已交付；未推送但确需交接时明确实际状态。

同步记录不授权 commit、push、合并、部署或关闭 Issue。每个节点都合入已确认的待同步需求及变更，保持正文需求版本与结论一致。更新前重读远端并保留他人内容、需求历史、其他阶段状态和旧候选证据索引。同一节点无实质变化时跳过写入，正式交接至多一条摘要。写入后读回，再将对应本地内容标为已同步；部分成功时保留其余待同步，结果不明时先查询。只要求方案或缺少远端更新授权时保留本地文本。

## 执行已授权操作

1. 合并前重新读取目标分支当前 base SHA、PR head SHA、必需检查、review 及合并状态。任一版本变化时，核实当前组合的差异并刷新受影响证据；head 未变不能代替 base 未变，不用旧组合的绿色结果放行。
2. 合并会自动部署时，触发前必须确认实际部署产物受有效验证约束。可以使用要求当前 base/head 组合通过检查的分支保护或合并队列，也可以由部署前检查保证最终合并产物通过后才部署。任一版本变化后旧结果必须失效并重新核验。仅有本地预合并通过或合并前重读不够；无法确认这些保证时保持待处理，不触发会自动部署的合并，不擅自修改 CI。
3. 用户已授权合并且本轮 PR 尚未合并时，按项目规则合并，并以预期 head 等条件约束实际合并对象。检查后 head 或 base 变化时回到前两步，由对应机制重新核验，不绕过分支保护。已合并记录仅用于该轮结果读回。读回已合并状态、目标分支和最终 SHA。进入队列或开启自动合并仍是待合并，不能记为成功。监看用户授权的当前操作到完成、失败或需要介入，不另建周期自动化。
4. 对比最终合并结果与已验证组合或产物，记录候选与最终版本的关系。包含未验证的额外行为变化时，补测或补审受影响范围，通过前不得部署该产物。自动部署流程若已绕过验证启动，按发布异常处理，停止继续发布并进入失败处理，不能只标记未验证后继续。
5. 对已授权且产物检查通过的部署执行项目现有发布入口，记录环境、产物及运行标识。重入时先核对现有运行，已有同版本部署时补验证，状态不明时先查询，不盲目重复触发。手动命令返回成功或 CI 绿色后，继续从实际环境读回运行版本，并验证入口和关键业务路径。

用户要求发布“最新版”时，只验证与本次需求有关的候选及实际产物，不顺带发布无关改动。无法隔离混入改动时说明影响并保持待决策。

## 发布后验证与失败处理

分别记录合并、部署执行、运行版本读回、冒烟和业务验收结果。读不到运行版本时写未确认，不把构建版本或预期配置当成部署证明。版本标识不可用时，使用可追溯的产物指纹及运行行为证据，并写明限制。

关键检查失败时停止继续发布，保存日志和现场，按已授权且适用的项目回退方式处理。缺少回退授权时先交付具体回退方案。不要无限重试、临时放宽检查或删除数据来恢复绿色。回退后再次读回运行版本并复验，记录实际恢复结果。

部署成功但业务验收未完成时，Issue 保持打开，标记已发布待验收。全部 AC 及交付条件通过后，按已有关闭授权更新并关闭 Issue，读回最终正文和状态；可使用 `dev-acceptance` 组织最终验收。

无应用部署的文档改动写明部署不适用，合并后仍验证默认分支文件或实际入口。交付报告包含候选与最终版本、目标环境、实际检查结果、未完成项和下一步。

合并、部署、回退结束或中止时，按上述同步规则集中更新实际结果。同一次连续发布及验收可以在交接时合并汇报，需他人介入的异常及时同步。即使 SHA 未变，新环境、部署或验收结果仍需更新，不要求为同步记录新增提交。
