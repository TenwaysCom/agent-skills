# 简单项目开发套件的设计

这套 skills 将一次需求的当前目标、变化和交付证据保存在同一个 Issue 中。每轮交付通过一个 PR 进入默认分支，在实际交付环境验收后完成需求。

## 为什么用 Issue 保存需求

对话适合讨论，Issue 适合接续工作。Issue 正文保存当前结论，需求演变保留过去的决定。开发者、测试人员和后续 agent 因此能找到同一份需求记录。

不同材料承担不同职责。

| 材料 | 记录内容 |
| --- | --- |
| Issue | 当前需求、范围、验收条件、进度、使用方法和需求演变 |
| commit 和 PR | 实际改动及其关联需求 |
| 测试与 review 结果 | 具体版本的行为检查和改动审查 |
| 部署及验收证据 | 实际运行版本、真实入口和业务结果 |

AC 是验收条件。每项 AC 使用稳定编号，并描述前置条件、操作和可观察结果。需求变化时保留原编号和历史，受影响的条件重新验证。

## 为什么分成五个 skills

需求整理、自测、review、业务验收和发布需要不同输入，也产生不同结论。把这些职责分开，可以单独调用一个阶段，并保留其他阶段的实际状态。

| Skill | 独立结论 |
| --- | --- |
| `dev-requirements` | 当前需求、范围、AC 和待澄清项 |
| `dev-test` | 已检查行为、失败和未覆盖场景 |
| `dev-review` | 发现及处置、受审版本、可合并结论 |
| `dev-acceptance` | 逐项业务结果、交付是否完成 |
| `dev-release` | 发布准备、实际合并与部署、运行验证和回退 |

写代码继续使用项目已有的开发工具，因此无需增加“开发”skill。五个 skills 共用 Issue，不增加流程调度 skill，也不要求互相安装。

## 为什么按交付方式区分项目

项目复杂度取决于交付约束。代码量和语言不足以决定流程。

| 判断点 | 简单项目 | 复杂项目 |
| --- | --- | --- |
| 交付单位 | 可独立验证和回退的改动 | 需要跨模块或跨系统协调晋级的改动 |
| PR | 每轮一个 PR 合入默认分支 | 先 PR 到 UAT，再 PR 到 main 或生产分支 |
| 发布 | 按需求敏捷发布 | 按窗口或批次晋级 |
| 验收 | 可先预览，部署后验证实际环境 | 有独立 UAT 和生产晋级条件 |

项目已有复杂流程时，通用套件只保留需求和证据，后续交给项目专用 skills。它不创建 UAT 分支，也不替代发布窗口。

部署后发现同一需求需要修复时，新补丁 PR 属于下一轮交付，仍关联原 Issue。这与 UAT 到 main 的两阶段晋级不同。已合并的 PR 仅保留为历史，不能代表新补丁的候选版本。

## 为什么结论必须绑定版本和环境

本地文件正确，不等于实际入口已生效。预览验收通过，也不等于生产部署完成。这些区别要求证据保留需求版本、代码或产物版本、环境、检查动作、实际结果和证据位置。

当代码、依赖、配置、环境或需求变化时，旧证据只保留其仍适用的范围。受影响结果需要重新验证。

自动部署尤其需要验证实际组合。PR head 未变时，目标分支 base 仍可能变化。各分支独立通过测试，不能证明合并组合通过。

因此，会自动部署的合并必须受当前组合检查或最终产物检查约束。版本变化会使旧结果失效。缺少这种保证时，流程停在待处理，不能等部署启动后再补验。

## 为什么分别记录各阶段状态

总体阶段用于说明下一步。测试、review、验收、合并和部署状态分别保存实际结果，不能用“已完成”覆盖缺失的证据。

总体阶段包括待澄清、待开发、开发中、待验收、待发布、已发布待验收和已完成。阻塞原因及解除条件单独记录，保留原阶段。

检查结果包括通过、失败、未执行、阻塞、需重跑和不适用。不适用需要理由。需求或版本变化后，受影响 AC 重新打开，原证据保留为历史。

关闭 Issue 表示全部适用 AC 和交付条件已满足。项目要求人工确认时，agent 的操作记录不能代替该人的批准。

## 自动化与权限边界

skills 提供 agent 工作指南和模板。分支保护、GitHub Actions、Meegle 节点和发布脚本由项目维护，套件本身不实现机器强制门禁。

调用 skill 不扩展操作授权。当前请求和项目约定决定是否允许远端写入、提交、合并、部署及关闭 Issue。已有明确授权继续有效。

缺少远端访问能力时，本地 Markdown 草稿保留当前记录并标记未同步。草稿不能证明远端状态已更新。

## 设计来源

设计提炼自[改进项目研发流程](codex://threads/01a1f27e-418e-7c13-a382-b8d75d0f26ce)会话。该会话使用持续更新的 Issue、可观察的验收条件、提交关联，以及合并后的真实入口检查。历史会话中的结果不代表当前项目的发布状态。
